# Database — pickup-game-manager

## Entity List

- A **Player** has many **PlayerStats** (one per game they appeared in).
- A **Player** appears in many **Games** through a **GameRoster** join table.
- A **Game** has many **Players** through **GameRoster**.
- A **Game** has at most one **GameResult** (nullable — only set when the game is completed).
- A **Game** has many **PlayerStats** (one per rostered player once stats are entered).
- A **PlayerStat** belongs to one **Game** and one **Player**.
- An **AuditLog** records every create, update, and delete across all entities.

## Schema Overview

### `players`
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | PK, generated |
| name | VARCHAR(100) | not null |
| position | VARCHAR(50) | e.g. goalkeeper, defender, midfielder, forward |
| created_at | TIMESTAMPTZ | not null, default now() |
| updated_at | TIMESTAMPTZ | not null, default now() |

### `games`
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | PK, generated |
| scheduled_at | TIMESTAMPTZ | date + time of the game; not null |
| location | VARCHAR(150) | free-text venue name |
| status | ENUM | `scheduled` / `completed` / `cancelled`; default `scheduled` |
| created_at | TIMESTAMPTZ | not null, default now() |
| updated_at | TIMESTAMPTZ | not null, default now() |

### `game_roster` (join table)
| Column | Type | Notes |
|--------|------|-------|
| game_id | UUID | FK → games.id, ON DELETE CASCADE |
| player_id | UUID | FK → players.id, ON DELETE CASCADE |
| PK | composite | (game_id, player_id) |

### `game_results`
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | PK, generated |
| game_id | UUID | FK → games.id, UNIQUE, ON DELETE CASCADE |
| score_team_a | INTEGER | not null, default 0 |
| score_team_b | INTEGER | not null, default 0 |
| created_at | TIMESTAMPTZ | not null, default now() |
| updated_at | TIMESTAMPTZ | not null, default now() |

### `player_stats`
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | PK, generated |
| game_id | UUID | FK → games.id, ON DELETE CASCADE |
| player_id | UUID | FK → players.id, ON DELETE CASCADE |
| goals | INTEGER | not null, default 0 |
| assists | INTEGER | not null, default 0 |
| yellow_cards | INTEGER | not null, default 0 |
| red_cards | INTEGER | not null, default 0 |
| minutes_played | INTEGER | not null, default 0 |
| created_at | TIMESTAMPTZ | not null, default now() |
| updated_at | TIMESTAMPTZ | not null, default now() |
| UNIQUE | (game_id, player_id) | one stat row per player per game |

### `audit_logs`
| Column | Type | Notes |
|--------|------|-------|
| id | UUID | PK, generated |
| entity_type | VARCHAR(50) | e.g. `Player`, `Game`, `GameResult`, `PlayerStat` |
| entity_id | UUID | ID of the affected record |
| action | ENUM | `CREATE` / `UPDATE` / `DELETE` |
| description | TEXT | brief human-readable summary of what changed |
| created_at | TIMESTAMPTZ | not null, default now() |

## Migration Strategy

TypeORM CLI migrations.

- Migrations live in `apps/api/src/database/migrations/`.
- Generate: `npx typeorm migration:generate apps/api/src/database/migrations/<Name> -d apps/api/src/database/data-source.ts`
- Run: `npx typeorm migration:run -d apps/api/src/database/data-source.ts`
- Revert: `npx typeorm migration:revert -d apps/api/src/database/data-source.ts`
- Never edit a migration file after it has been run in any environment.

## Delete Strategy

Hard deletes throughout. Records are permanently removed. The `audit_logs` table provides a before-the-fact record of what existed and when it was deleted — that is sufficient for this use case.

## Audit Trail

A dedicated `audit_logs` table. Entries are written by the NestJS services (not database triggers) immediately after any successful create, update, or delete operation. The `description` column stores a plain-text summary (e.g., `"Player 'Carlos' deleted"`, `"Game on 2026-11-08 updated: status changed to completed"`).

No JSONB payload — full before/after diffs are out of scope for v1.

## Primary Keys

UUID for all entities. Generated by the database (`gen_random_uuid()`) and mapped via TypeORM's `@PrimaryGeneratedColumn('uuid')`.

## JSON Columns

None.
